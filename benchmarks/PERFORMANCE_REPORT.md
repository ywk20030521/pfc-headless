# pfc-headless 执行授权闸门性能报告

**日期：** 2026-11-27
**基准脚本：** `benchmarks/benchmark_authorization_gate.py`
**原始数据：** `benchmarks/results.json`
**命令：** `python benchmarks/benchmark_authorization_gate.py --rounds 5`
**环境：** Python 3.13.14 / Windows 11 (10.0.26300) / psutil 7.2.2
**范围：** 纯 Python 闸门路径与本地 JSON 持久化；**未连接 itasca-mcp / Bridge / PFC Console**。

---

## 1. 方法

- 每个场景先预热，再执行 5 轮；每轮 N 次调用，记录单次调用 `perf_counter` 延迟。
- 资源消耗：`time.process_time`（CPU）、`psutil.Process.memory_info().rss`（进程常驻内存）、`tracemalloc`（Python 分配峰值，单独一轮，避免污染延迟测量）。
- 稳定性：每轮输出归一化为可比较签名；统计异常次数、不同输出数量、跨轮 RSS 增长。
- 磁盘场景在临时目录运行并在结束后清理；不产生工作区副作用。

## 3. 稳定性

- **异常数**：全部 7 个场景 0 次非预期异常；预期拒绝路径均返回 `HeadlessError`。
- **确定性**：全部场景归一化输出签名数量 = 1，跨轮行为一致。
- **内存**：纯内存场景 RSS 增长 0–28 KB；落盘场景约 +0.97 MB（临时项目与缓存）；CLI 场景 RSS 下降约 26 MB（临时目录清理后回收），无单调增长趋势。
- **CPU / 墙钟一致性**：纯闸门 CPU 时间与墙钟同量级；CLI 场景 CPU/轮 1.9 s 对应 100 次调用，主要来自参数解析与模块初始化，不是授权校验本身。

## 4. 结果分析

1. **闸门逻辑本身不是瓶颈。** 纯授权解析 P95 为 0.0082 ms，Run 记录复核 P95 为 0.0011 ms；相对真实 PFC 仿真（分钟级）可忽略。安全校验没有引入有实际问题的影响。
2. **成本集中在 I/O 与 CLI 启动。** Run 准备落盘约 49 ms/次，CLI 无授权拒绝约 161 ms/次；差异来自 `argparse` 构建与模块导入，以及项目/用例 JSON 写入。批量场景应优先调用库级 `prepare_project_case()`，避免逐 Run 启动 CLI 进程。
3. **拒绝路径开销可控。** 历史 Run 与缺字段拒绝均在微秒级，适合放在提交边界逐次执行。
4. **已知测量边界。** 磁盘场景使用临时目录与本地文件系统；网络盘、并发写入和真实 PFC 执行未纳入本次基准。

## 5. 改进建议

| 优先级 | 建议 | 理由 |
|---|---|---|
| P1 | 批量准备复用库入口 `prepare_project_case()`，CLI 仅作人工/单次入口 | 消除约 160 ms/次的 CLI 启动开销 |
| P1 | 后续 PR 为 `ResearchLedger`/项目写入增加文件锁与事务语义 | 当前为单进程参考实现，并发写未在基准覆盖 |
| P2 | 对不可变授权按 `authorization_id` 缓存已校验对象，仅在版本字段变化时重算 | 可进一步降低批量场景重复字段校验，不降低闸门强度 |
| P2 | 将本脚本接入 CI 作为回归门槛（如纯闸门 P95 < 0.05 ms、确定性 = 1） | 防止后续改动把安全边界变成性能瓶颈 |
| P2 | 补充真实 Bridge/PFC 场景的端到端计时 | 本次只覆盖闸门，不能代表真实科研任务吞吐 |

## 6. 结论

执行授权闸门在关键路径上开销为**微秒级**，稳定性满足要求；主要性能成本来自项目落盘与 CLI 启动，可通过库级复用和后续并发改造优化。**本结果不宣称真实 PFC 环境性能或端到端科研吞吐。**
